# Minishell
The Mini Shell project aims to create a simplified version of a Unix-like shell that emulates basic functionalities of BASH. It functions as a command processor, prompting users to enter commands in a terminal or text window. The shell supports a range of built-in commands such as cd, pwd, exit, echo, fg, bg, and jobs, along with the execution of external commands by forking child processes. The main goal of this project is to implement a basic shell interface that allows users to execute commands, manage jobs, and handle signals effectively using system calls and inter-process communication (IPC) mechanisms.One of the key features of the Mini Shell is the customizable prompt, which defaults to msh>, but can be modified using the PS1 environment variable. The user can change the prompt with the format PS1=NEW_PROMPT, ensuring there are no spaces between the variable name and value. This dynamic prompt customization helps users personalize their shell environment.The shell allows users to execute external commands by creating a child process using fork() and executing the command with execvp(). The parent process waits for the child to complete, ensuring that the prompt is displayed only after the child process has finished executing. If no command is entered, the prompt is redisplayed, providing a continuous user experience. Additionally, the shell supports special variables like the exit status of the last command ($?), the process ID of the shell ($$), and the shell's executable path ($SHELL), making it easy for users to access important system information.Signal handling is another crucial feature. The shell processes signals such as SIGINT (Ctrl+C) and SIGTSTP (Ctrl+Z). When a user presses Ctrl+C, the shell sends a SIGINT signal to the foreground process, terminating it. If no foreground process is running, the prompt is redisplayed. Similarly, pressing Ctrl+Z sends a SIGTSTP signal to the foreground process, pausing it and placing it in the background. The shell also allows users to bring background processes to the foreground with the fg command, send stopped processes to the background with bg, and list background processes using the jobs command.Job control is an integral part of the shell, allowing users to manage multiple background processes. For instance, a user can execute a command with an ampersand (&) to run it in the background. The shell keeps track of these background processes, cleaning them up using wait() once they terminate. The jobs command displays details about all running background processes, and fg can be used to bring any background job to the foreground.
The project also incorporates pipe functionality, allowing the user to connect multiple processes in a pipeline. For example, a command like ls | wc or ls -l /dev | grep tty | wc -l enables inter-process communication by passing the output of one process as the input to the next, all within a single command line. The shell dynamically creates pipes and child processes as needed, facilitating seamless execution of piped commands.Overall, this Mini Shell project covers essential aspects of shell functionality, including command execution, job control, signal handling, and process communication, providing a basic but powerful command-line environment for users to interact with their system. It serves as an excellent learning experience for understanding the inner workings of Unix-based shells and the underlying system calls
